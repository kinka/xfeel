# xfeel-v2 技术选型表

## v1 默认选型

| 层 | 默认选型 | 后续备选 | 现在不选什么 | 结论 |
| --- | --- | --- | --- | --- |
| Runtime | Bun + TypeScript | Node.js | 多语言服务拆分 | 当前代码已基于 Bun 跑通，先保持简单 |
| API | Fastify | Hono | NestJS | Fastify 足够稳，接口层轻量清楚 |
| DB | SQLite + WAL | SQLite schema / index 优化 | 外部数据库服务作为主库 | 家庭日志规模下 SQLite 足够，备份和部署成本最低 |
| Text search | FTS5 | 外部搜索引擎 | OpenSearch / RAGFlow | 原文、摘要、标签检索用 FTS5 覆盖 |
| Queue | 进程内/定时任务 | 需要时再加轻量 job runner | 外部工作流平台 | 日终归档任务先做简单，避免为事务队列付复杂度 |
| Vector | 暂不引入 | SQLite 扩展 / 小型本地向量索引 | 独立向量数据库 | 当前以结构化查询和 FTS5 为主，向量不是第一阶段关键 |
| File store | 本地文件系统 | MinIO / S3 | 一开始上对象存储 | 多模态后置，本地文件足够 |
| LLM | Ollama / OpenAI-compatible API | 独立推理服务 | stateful agent runtime | LLM 只做推理，不保存系统主状态 |
| ASR | 后续接入 | 中文语音转写服务 / 本地转写模型 | 第一阶段投入语音流水线 | 语音先放 Phase 3，转成文本后复用同一管线 |
| VLM | 后续接入 | MiniCPM-o / Qwen-VL | 图片/视频先行 | 图片视频理解等文本闭环稳定后再做 |

## 为什么 SQLite + FTS5 足够

当前产品目标不是高并发 SaaS，而是家庭情绪日志、成长记录和长期回顾。

SQLite 的收益更直接：

- 单文件，方便本地优先、备份、迁移和调试
- WAL 模式支持当前读写模型
- 结构化字段适合实体、情绪、标签、事件类型过滤
- FTS5 足够支撑原文和摘要检索
- 减少部署面，避免数据库、队列、向量库一起扩张带来的运维成本

迁移触发条件应当很具体，例如：

- 单机写入压力明显成为瓶颈
- 多用户远程部署需要更强隔离和并发
- 日志规模增长到 SQLite 查询优化无法接受
- 多模态检索体验稳定后，确实需要独立向量服务

在这些条件出现前，不引入外部主数据库。

## 产品优先级

| 优先级 | 能力 | 说明 |
| --- | --- | --- |
| P0 | 情绪日志沉淀 | 从对话中抽取情绪、强度、触发事件、正负向 |
| P0 | 成长记录沉淀 | 睡眠、喂养、健康、里程碑、照护等事件结构化 |
| P0 | 持续对话 | 用户当天可以连续聊天，系统基于历史记忆响应 |
| P0 | 日终总结归档 | 当天对话总结成可读日记，并抽取事件更新图谱 |
| P1 | 知识图谱质量 | 实体关系、情绪趋势、成长时间线、因果线索 |
| P2 | 多模态输入 | 语音 ASR、图片理解、视频切段 |

## 模型分层建议

| 层 | 模型/方式 | 角色 |
| --- | --- | --- |
| 轻量分类 | 本地 LLM + 规则兜底 | 判断是否值得归档 |
| 结构化抽取 | 本地 LLM 或 OpenAI-compatible API | 抽取事件、情绪、实体、标签 |
| 对话响应 | 常驻/按需 LLM | 结合当天上下文和召回记忆回复用户 |
| 日终归档 | LLM + 规则归一化 | 总结当天对话，生成日记和事件 |
| 图谱分析 | 规则/启发式优先，LLM 辅助 | 去重、因果线索、阶段检测 |
| ASR/VLM | 后续接入 | 语音、图片、视频转成可归档事实 |

## 为什么不是 Letta / stateful agent runtime

| 问题 | 在 xfeel-v2 里的影响 |
| --- | --- |
| 状态落在 agent runtime 内 | 不利于把家庭记忆做成稳定、可审计、可迁移的底座 |
| Channel 和记忆状态耦合 | 不利于公众号、Web、CLI 等多入口并行扩展 |
| 图谱和归档难以控制 | 日终总结、事件去重、因果更新需要显式数据模型 |
| 多模态仍要旁路 | 语音、图片、视频最终还是要落到结构化记忆 |

Agent 可以作为上层交互形态，但不能成为主存储。

## v1 到 v2 的升级点

| 现在先不做 | 触发条件 | 再升级什么 |
| --- | --- | --- |
| 外部主数据库 | 暂不计划；优先通过 SQLite schema、索引和归档策略解决 | 只有产品形态变化后再重评估 |
| 外部工作流平台 | 日终归档和多模态任务需要可靠重试 | 增加轻量队列或工作流 |
| 独立向量数据库 | 文本图谱稳定后，需要跨图片/视频检索 | 先评估本地向量索引，再决定是否外置 |
| MinIO / S3 | 多机部署或远程同步明确 | 把 `files` 包抽象切到对象存储 |
| 视频高级理解 | 视频量增大且有明确回顾需求 | 切段、抽帧、音轨转写、片段摘要 |
